YDevDesk Dokümantasyon Portalı

Kullanım, Eklenti ve Tema Rehberi

YDevDesk'i dakikalar içinde kurun, klavye kısayolları ile çalışma alanınızı hızlandırın, ajanlarınızın ortak hafızasını (Bilgi Ağı) kurun ve kendi eklentilerinizi, temalarınızı veya çekirdek modüllerinizi geliştirin.

Kurulum (Linux / macOS / Windows)

YDevDesk, Tauri v2 ve Rust çekirdeği üzerine kurulu yerel bir masaüstü uygulamasıdır. Harici bir çalışma zamanı (Node.js veya Electron) kurmanıza gerek kalmadan çalışır.

Linux (Önerilen Tek Komut)

Arch, CachyOS, Ubuntu, Debian, Fedora ve diğer modern Linux dağıtımlarında en son sürümü otomatik kurar:

bash — Tek Komut Kurulum 
curl -fsSL https://raw.githubusercontent.com/YagYz/YDevDesk/main/install.sh | bash

Ubuntu / Debian (APT Deposu)

APT deposunu ekleyerek güncellemeleri standart apt upgrade akışıyla alabilirsiniz:

bash — APT Kurulumu 
echo 'deb [trusted=yes] https://yagyz.github.io/YDevDesk/apt ./' | sudo tee /etc/apt/sources.list.d/ydevdesk.list
sudo apt update && sudo apt install -y ydevdesk
Linux Wayland & NVIDIA Notu

install.sh betiği, Wayland + NVIDIA ekran kartlarında WebKitGTK beyaz ekran sorununu önlemek için WEBKIT_DISABLE_DMABUF_RENDERER=1 ortam değişkenini içeren bir sarmalayıcıyı otomatik olarak kurar. AppImage dosyasını elle çalıştırıyorsanız bu değişkeni komutun başına ekleyebilirsiniz.

macOS (Apple Silicon & Intel)

GitHub Releases sayfasından işlemcinize uygun .dmg paketini (aarch64.dmg veya x64.dmg) indirin, uygulamayı /Applications klasörüne sürükleyin ve ilk çalıştırma öncesinde karantina niteliğini kaldırın:

zsh — macOS İlk Çalıştırma İzni 
xattr -cr /Applications/ydevdesk.app

Windows (64-bit)

En son sürümden *-setup.exe (NSIS) kurulum dosyasını indirip çalıştırın. Kurulum tamamlandığında Başlat menüsünde YDevDesk kısayolu hazır olacaktır.

İlk Açılış & Bağlantılar

YDevDesk ilk açıldığında bilgisayarınızda kurulu AI kodlama ajanlarını (agy, claude, codex) otomatik olarak algılar. Aşağıdaki adımlarla çalışma ortamınızı kişiselleştirebilirsiniz:

  • Proje Kök Dizinleri: Ayarlar → Bağlantılar bölümünden sık çalıştığınız proje klasörlerini (ör. /mnt/Depo/Projeler veya ~/Projects) ekleyin. Git durumu, dosya haritası ve hızlı terminal açma bu dizinleri kullanır.
  • Homelab Servisleri (İsteğe Bağlı): YDevHub veya YNetMon kullanıyorsanız URL ve API anahtarını ekleyerek notlar, görevler, Bilgi Ağı ve canlı ağ trafiği panellerini etkinleştirebilirsiniz.
  • Ajan Hafızası (Bilgi Ağı): Ajanlarınızın birbirinin işini görmesi için Ayarlar → Bilgi Ağı sekmesine bakın; ayrıntılar Bilgi Ağı bölümündedir.
  • İsteğe Bağlı Senkronizasyon: Birden fazla bilgisayarda çalışıyorsanız Ayarlar → Senkronizasyon sekmesinden şifreli GitHub Secret Gist eşitlemesini açabilirsiniz.

Ayarlar Sekmeleri

Ayarlar penceresinde şu sekmeler bulunur: Bağlantılar, Modüller, Temalar, Eklentiler, Komutlar, Bildirimler, Ajanlar, Bilgi Ağı, Senkronizasyon ve Sürüm.

Yerleşik Paneller (Modüller)

Çalışma alanına eklenebilen yerleşik paneller: Oturumlar, Ajan Durumu, Araç Akışı, Git, Dosya Yoğunluğu, Hızlı Eylemler, Görevler, Notlar, Bilgi Ağı ve YNetMon Ağ. Görevler, Notlar ve YNetMon Ağ panelleri YDevHub / YNetMon bağlantısı gerektirir; hangilerinin görüneceğini Ayarlar → Modüller bölümünden seçebilirsiniz.

Klavye Kısayolları

Dockview çalışma alanı ve hızlı komut paleti tamamen klavye odaklı kullanım için tasarlanmıştır:

Kısayol İşlev Açıklama

Terminal & Click-to-Cursor

YDevDesk, Rust tabanlı yerel PTY (portable-pty) ve yüksek performanslı terminal işleyici kullanır. Klasik masaüstü terminallerine göre çok daha düşük bellek tüketimiyle birden fazla kabuk oturumunu yan yana çalıştırabilirsiniz.

  • Click-to-Cursor: Uzun bir bash/zsh komutunu düzenlerken ok tuşlarına basılı tutmak yerine komut satırında istediğiniz karaktere tıklayarak imleci doğrudan oraya taşıyabilirsiniz.
  • Terminal Şablonları (Presets): Sık çalıştırdığınız SSH bağlantıları, ajan başlatıcıları veya proje betiklerini şablon olarak kaydedip tek tıkla yeni sekmede açabilirsiniz.
  • Tema Eşleşmesi: Uygulama temasını değiştirdiğinizde tüm açık terminallerin arka plan, ön plan, imleç ve seçim renkleri anında güncellenir.

Markdown Otomatik Açma & Dosya Aç

Yapay zeka ajanları sık sık plan dosyaları, teknik raporlar veya dokümanlar üretir. YDevDesk'in yerleşik Markdown Görüntüleyici paneli bu dosyaları doğrudan çalışma alanınızın merkezinde okunaklı biçimde sunar:

  • Otomatik Açma: Ajan çıktılarında veya dosya ısısı (File Heat) panelinde oluşturulan/güncellenen .md dosyalarını tek tıkla veya otomatik izleme ile yeni sekmede görüntüleyin.
  • Dosya Aç: Üst araç çubuğundan veya eklenti/modül SDK'sından (openMarkdown) bilgisayarınızdaki herhangi bir Markdown dosyasını anında açabilirsiniz.
  • Canlı Yenileme: Dosya diskte değiştiğinde içerik otomatik olarak tazelenir.

AGY, Claude Code & Codex Ajanları

YDevDesk, yerel makinenizde çalışan üç büyük kodlama ajanını tek arayüzde birleştirir:

  • Antigravity (AGY): ~/.gemini/antigravity-cli/ altındaki konuşmaları, oturum kimliklerini ve token kullanımını okur.
  • Claude Code: ~/.claude/ oturum geçmişini ve proje bazlı sohbetleri listeler.
  • OpenAI Codex: ~/.codex/ oturum kayıtlarını algılar ve tek tıkla devam etmenizi sağlar.

Oturumlar panelinde herhangi bir konuşmayı sabitleyebilir, özel bir takma ad (alias) verebilir ve tek tıkla ilgili ajanın --resume komutuyla yerleşik terminalde kaldığınız yerden sürdürebilirsiniz.

Ayarlar → Ajanlar sekmesi kurulu ajanları tarar; normal veya bypass kipinde başlatmanızı, güncellemenizi, terminalde açmanızı ve eksik olanı kurmanızı sağlar. Ajanların birbirinin çalışmasını görmesi için Bilgi Ağı hafızasını kullanın.

Güvenli Oturum Silme

Artık ihtiyacınız olmayan eski ajan oturumlarını YDevDesk içinden doğrudan temizleyebilirsiniz. Güvenli oturum silme mekanizması:

  • Silme işlemi öncesinde açık onay ister; kazara veri kaybını önler.
  • Yalnızca ilgili ajanın doğrulanmış oturum dizini içindeki (yol doğrulamalı / canonicalized) dosyaları kaldırır; sistem veya proje dosyalarına dokunmaz.
  • Sabitleme ve özel isim kayıtlarını da otomatik olarak temizler.

Kota & Maliyet Takibi

Analitik paneli herhangi bir harici eklenti veya bulut aracı gerektirmeden yerel oturum günlüklerinden 1 günlük, 7 günlük ve 30 günlük pencerelerde detaylı kullanım çıkarır:

  • Token & USD Maliyet: Girdi, çıktı ve önbellek (cache) token sayılarını model bazlı tahmini USD maliyetiyle birlikte gösterir.
  • Kota Eşikleri: 5 saatlik ve haftalık kullanım kotalarını canlı ilerleme çubuklarıyla takip eder; belirlediğiniz eşiğe ulaşıldığında yerel masaüstü bildirimi ve sesli uyarı verir.
  • Çoklu Cihaz Toplamı: Şifreli Gist senkronizasyonu açıksa tüm cihazlarınızdaki kullanım özetleri tek grafikte birleştirilir.

Bilgi Ağı: Nedir ve Nasıl Çalışır?

Ayrıntılı rehber

Sisteminizde hangi dosyaların değiştiği, yedekler, elle kurulum ve elle kaldırma, gizlilik ve veri akışı için: Ayrıntılı rehber → knowledge.html

Bilgi Ağı, Claude Code, Codex ve Antigravity (AGY) oturumlarınızın ortak kullandığı yerel bir hafızadır. Bir ajan işini bitirince ne yaptığını kısa bir kayıtla yazar; bir sonraki oturumda (aynı ya da başka bir ajan) işe başlamadan önce bu kayıtları okuyarak kaldığı yeri görür. Böylece aynı işi tekrarlamaz veya önceki işi bozmaz.

  • Yerel SQLite: Kayıtlar bilgisayarınızdaki bir SQLite veritabanında (WAL kipinde) tutulur. Varsayılan konum, işletim sisteminin veri dizini altındaki com.yagyz.ydevdesk/knowledge.db dosyasıdır. Özel bir mutlak yol (veya ~/ ile başlayan yol) Ayarlar → Bilgi Ağı → Veritabanı yolu alanından verilebilir; göreli yollar süreçler arası farklı veritabanlarına yazdırdığı için reddedilir.
  • Kayıt alanları: servis (proje adı), başlık, özet, etiketler, cihaz adı ve yazan ajan (claude, codex, agy, user veya unknown). Ajan adı doğrulanmamış bir iddiadır.
  • Etiketler: Özet içinde [[servis/konu]] biçiminde yazılan etiketler otomatik ayrıştırılır; ayrıca tags alanıyla ek etiket verilebilir.
  • YDevHub opsiyoneldir: Homelab'ınızda YDevHub varsa kayıtlar oraya da eşlenebilir. YDevHub olmadan Bilgi Ağı tamamen yerel çalışır.
  • Ajan erişimi (MCP): Ajanlar hafızaya ydevdesk --mcp komutuyla başlayan, pencere açmayan bir stdio MCP sunucusu üzerinden erişir. Aynı servis katmanı uygulama arayüzü tarafından da kullanılır.
  • Arayüzde: Bilgi Ağı paneli kayıtları listeler; Ctrl + K komut paletindeki Hafıza kipi ile (servis adı Hızlı Kayıt, ajan user) elle kayıt ekleyebilirsiniz. Ayarlar Ayarlar → Bilgi Ağı sekmesindedir.

Depolama Modları

Ayarlar → Bilgi Ağı → Depolama altında üç mod vardır. Varsayılan Yerel'dir. YDevHub bağlantısı (Ayarlar → Bağlantılar) yapılandırılmamışsa diğer iki seçenek seçilemez.

ModYazmaOkuma
Yerel Yalnızca bu cihazdaki SQLite veritabanı. Yerel veritabanı.
YDevHub Yalnızca YDevHub. Hub'a ulaşılamazsa kayıt yerel gönderim kuyruğuna (outbox) alınır. Doğrudan YDevHub'dan. Hub erişilemezse okuma hata verir; yerel veritabanına geri düşülmez.
İkisi birden Önce yerel veritabanına, sonra YDevHub'a. Hub erişilemezse kayıt yine yerelde kalır ve hub için kuyruğa alınır. Yerel veritabanı.

Hub kapalıyken kuyruk

  • Gönderilemeyen kayıtlar yerel veritabanındaki outbox tablosunda bekler. Uygulama açıkken 30 saniyede bir, ayrıca her başarılı MCP kaydından sonra arka planda boşaltılır; aynı anda en çok 20 kayıt işlenir.
  • Geçici hata (ağ, 5xx, 408, 429) halinde kayıtlar kuyrukta kalır ve sonra yeniden denenir. Kalıcı hata (diğer 4xx) alan kayıt atlanır ve sonrakiler engellenmez; deneme sayısı üst sınıra ulaşan kayıt artık denenmez ve kuyrukta kalır.
  • Gönderim en-az-bir-kez (at-least-once) garantilidir: yanıtın kaybolduğu nadir durumlarda aynı kayıt hub'a iki kez ulaşabilir.
  • Kapalı çalışma izninde arka plan boşaltması da ağa çıkmaz.
  • Ayarlar sekmesinin altındaki durum satırı kayıt sayısını ve kuyruktaki kayıt sayısını gösterir.

Çalışma İzni

Ajanların MCP araçlarını kullanıp kullanamayacağını Ayarlar → Bilgi Ağı → Çalışma izni belirler:

SeçenekDavranış
KapalıMCP araçları knowledge devre dışı (kapalı) yanıtı verir. Arka plan kuyruk boşaltması da çalışmaz.
Yalnızca uygulama açıkkenYDevDesk çalışırken araçlar çalışır. Uygulama her 5 saniyede bir app.alive nabız dosyasını günceller; 15 saniyeden eski ya da yok sayılan nabız "uygulama kapalı" demektir ve araçlar knowledge devre dışı (uygulama kapalı) yanıtı verir.
Her zaman (varsayılan)Uygulama kapalı olsa bile araçlar çalışır.
MCP sunucusu bir daemon değildir

ydevdesk --mcp arka plan servisi olarak çalışmaz; ajan oturumu açıldığında ajan tarafından başlatılır ve oturumla birlikte kapanır. "Her zaman", sunucunun sürekli çalıştığı anlamına gelmez; yalnızca ajan onu başlattığında uygulamanın açık olmasının gerekmediği anlamına gelir. Uygulama arayüzündeki panel ve Hızlı Kayıt, kullanıcı tarafından yönetildiği için bu kapıya tabi değildir.

Ayar dosyası bozuksa kapalı kalır

Ayarlar ~/.config/ydevdesk/knowledge.json dosyasında tutulur. Dosya yoksa varsayılanlar kullanılır; dosya var ama okunamıyor ya da ayrıştırılamıyorsa özellik güvenli tarafta kalır: çalışma izni Kapalı sayılır. Dosyayı düzeltin veya silin.

MCP Araçları

Sunucu ydevdesk-knowledge adıyla kaydedilir (stdio, JSON-RPC 2.0) ve iki araç sunar. Araç açıklamaları ve yanıt metinleri Türkçedir.

knowledge_log

Yapılan işi hafızaya kaydeder. İş bittiğinde çağrılır.

AlanTürAçıklama
servicestring, zorunluServis veya proje adı (en çok 100 karakter, kontrol karakteri yok).
titlestring, zorunluKısa, tek satırlık başlık (en çok 200 karakter).
summarystring, zorunlu1-2 cümlelik özet, [[servis/konu]] etiketleri içerebilir (en çok 8000 karakter).
tagsstring dizisi, isteğe bağlıEk etiketler (en çok 20 adet, her biri en çok 64 karakter; [ ve ] içeremez).

Başarıda kaydedildi #<id> döner; hub kuyruğuna alındıysa sonuna (hub kuyruğunda) eklenir.

knowledge_read

Son kayıtları okur. İşe başlamadan önce ilgili servis için çağrılır. Tüm alanlar isteğe bağlıdır.

AlanTürAçıklama
servicestringServis/proje adına göre süzer.
searchstringMetin araması (büyük/küçük harf duyarsız).
tagstringEtikete göre süzer.
limitintegerVarsayılan 10, en çok 100.
  • Çıktı, başa eklenen bir "güvenilmeyen veri" uyarısıyla ve her çağrıda rastgele bir nonce içeren <knowledge_entries> sınırlayıcılarıyla sarılır; kayıt içeriği bu sınırı taklit edemez.
  • Her kayıt servis, id, başlık, ajan@cihaz, UTC zamanı ve "doğrulanmamış" ibaresiyle listelenir. Kontrol karakterleri temizlenir; tek kayıt özeti 2000, toplam çıktı yaklaşık 20.000 karakterle sınırlıdır. Sınır aşılırsa kaç kaydın gösterilmediği yazılır.
  • Kayıt yoksa kayıt yok döner.

Uygulamadan Tek Tık Kurulum

Ayrıntılı rehber → hangi dosyalar değişir

Ayarlar → Bilgi Ağı → Ajanlara ekle bölümü, Claude Code, Codex ve AGY için iki şeyi sizin yerinize yapar:

  1. MCP kaydı: ydevdesk-knowledge sunucusunu, komut olarak uygulamanın kendi ikili dosyası ve --mcp argümanıyla ajanın kullanıcı (genel) yapılandırmasına ekler.
  2. Genel kural dosyası bloğu: Ajanın genel kural dosyasına, <!-- ydevdesk:knowledge:start --> ve <!-- ydevdesk:knowledge:end --> işaretçileri arasında İngilizce bir kural bloğu ekler (ajana işe başlarken knowledge_read, iş bitince knowledge_log çağırmasını söyler).

Nasıl ilerler

Ajanları işaretleyip Önizle ve ekle'ye basarsınız; hedef yollar, eylem ve yazılacak parça önizlemede gösterilir, Onayla ve yaz'a basmadan hiçbir dosya değişmez. Yalnızca işaretçili blok yazılır, ilk yazmadan önce <dosya>.ydevdesk.bak yedeği alınır, yazma atomiktir ve ikinci tıklama çoğaltmaz. Kaldır eklenenleri geri alır. Adım adım akış, hata durumları ve elle kaldırma için ayrıntılı rehbere bakın.

AjanMCP kaydıGenel kural dosyası
Claude Codeclaude mcp add --scope user~/.claude/CLAUDE.md
Codex~/.codex/config.toml içinde işaretçili [mcp_servers.ydevdesk-knowledge] tablosu~/.codex/AGENTS.md
AGY~/.gemini/config/mcp_config.json içindeki mcpServers nesnesine birleştirme~/.gemini/config/GEMINI.md (belgelenmiş bir genel kural yolu değildir, ancak AGY ile denenerek doğrulanmıştır; bkz. Bilinen Sınırlar)

Elle Kurulum

Ayrıntılı rehber → elle kurulum Elle kaldırma

Tek tık kurulumu kullanmak istemezseniz her ajan için MCP sunucusunu elle kaydedebilirsiniz. Üç örnekte de komut, YDevDesk ikili dosyasının tam yolu ve argüman --mcp olmalıdır. Yolu bulmak için:

  • Linux (install.sh): ~/.local/bin/ydevdesk (argümanları AppImage'a ileten başlatıcı). AppImage'ı elle çalıştırıyorsanız $APPIMAGE yolunu kullanın.
  • Linux (APT / .deb): command -v ydevdesk çıktısı.
  • macOS: /Applications/ydevdesk.app/Contents/MacOS/ydevdesk (uygulamayı başka yere taşıdıysanız ona göre).
  • Windows: kurulum dizinindeki ydevdesk.exe; yol boşluk içeriyorsa tırnaklayın.

Claude Code

bash — Claude Code MCP kaydı 
claude mcp add --scope user ydevdesk-knowledge -- <ydevdesk yolu> --mcp

Codex

~/.codex/config.toml dosyasına şu tabloyu ekleyin (yol için TOML literal string, yani tek tırnak, kullanmak ters bölü içeren Windows yollarında güvenlidir):

~/.codex/config.toml 
[mcp_servers.ydevdesk-knowledge]
command = '<ydevdesk yolu>'
args = ["--mcp"]

Antigravity (AGY)

~/.gemini/config/mcp_config.json dosyasındaki mcpServers nesnesine girdiyi ekleyin; dosyadaki diğer sunucuları silmeyin:

~/.gemini/config/mcp_config.json 
{
  "mcpServers": {
    "ydevdesk-knowledge": {
      "command": "<ydevdesk yolu>",
      "args": ["--mcp"]
    }
  }
}

Kaydı yaptıktan sonra ajanı yeniden başlatın. Kural bloğunu da eklemek için sonraki bölümdeki şablonları kullanın; kural bloğu olmadan araçlar kullanılabilir ama ajan onları kendiliğinden çağırmayabilir.

Kural Şablonu İndirme Bağlantıları

Ajanlara hafızayı ne zaman okuyup yazacaklarını anlatan kural bloğu İngilizcedir ve üç şablon dosyasında aynı metinle sunulur. Her dosyanın başında kısa bir kurulum notu vardır; işaretçiler (ydevdesk:knowledge:start/end) arasındaki blok yönetilen bölümdür: güncellenmiş bloğu yeniden yapıştırırsanız eskisinin yerine geçer.

ŞablonNereye eklenir
agents/CLAUDE.md Claude Code: ~/.claude/CLAUDE.md dosyasının sonuna ekleyin.
agents/AGENTS.md Codex (ve AGENTS.md okuyan ajanlar): ~/.codex/AGENTS.md dosyasının sonuna ekleyin.
agents/GEMINI.md Antigravity (AGY): tüm projelerde geçerli olması için ~/.gemini/config/GEMINI.md dosyasına ekleyin; yalnızca bir proje için kullanacaksanız o projenin dizinindeki GEMINI.md dosyasına ekleyin (tek tık kurulum genel yolu kullanır).
bash — Claude Code için ekleme örneği

Güvenlik Notları

Ayrıntılı rehber → güvenlik modeli Gizlilik & veri akışı

  • Kayıtlar güvenilmeyen veridir. Hafızadaki metni başka oturumlar, başka ajanlar veya YDevHub üzerinden gelen veriler yazmış olabilir. knowledge_read çıktısı uyarı ve rastgele sınırlayıcılarla sarılır ve kural şablonu ajana kayıtlardaki talimatları asla izlememesini söyler. Yine de bu bir kesin garanti değil, savunma katmanıdır.
  • Sır yazmayın. Token, parola, API anahtarı veya dosya içeriğini kayıt alanlarına koymayın. Kayıtlar yerel veritabanında düz metin olarak durur ve YDevHub modunda hub'a gönderilir.
  • Çalışma izni bir güvenlik sınırı değildir. Aynı kullanıcı olarak çalışan herhangi bir süreç hem ayar dosyasını hem veritabanını doğrudan okuyup yazabilir. İzin, ajanların araçları kullanmasını yönetmek içindir; yetkisiz süreçlere karşı koruma sağlamaz.
  • Ayar bozuksa kapalı kalır. Bozuk knowledge.json özelliği sessizce açmaz; Kapalı sayılır.
  • Dosya izinleri. Yeni veritabanı dosyası Unix sistemlerde 0600 izniyle, yeni klasör 0700 ile oluşturulur. Mevcut bir klasörün izinleri değiştirilmez.
  • Hub isteği. YDevHub çağrıları X-API-Key başlığıyla yapılır ve yönlendirmeler (redirect) izlenmez; anahtar başka bir adrese gitmez. Zaman aşımı 5 saniyedir.
  • Kurulum değişiklikleri. Tek tık kurulum önizleme olmadan yazmaz, yazmadan önce yedek alır ve yalnızca işaretçili bloğa dokunur.

Bilinen Sınırlar

Ayrıntılı rehber → bilinen sınırlar

  • AGY genel kural dosyası resmi olarak belgelenmemiştir. Tek tık kurulum ~/.gemini/config/GEMINI.md dosyasına yazar; yol gerçek AGY ile denenerek doğrulandı ve AGY sürümüne bağlıdır. Aynı bloğu iki yere birden koymayın. Ayrıntı: rehber.
  • Windows ve Linux'ta MCP yalnızca derleme/test düzeyinde doğrulandı. Bu platformlarda gerçek bir ajanla uçtan uca kullanım denenmemiştir; sorun yaşarsanız bildirin.
  • Hub-only modda kuyruk davranışı. Hub'a ulaşılamazsa kayıt yalnızca yerel kuyruğa alınır, yerel kayıt listesinde görünmez (knowledge_log bu durumda kayıt numarası döndürmez) ve hub'a gidene kadar okunamaz. Kuyruğun boşalması uygulamanın (ya da başka bir MCP çağrısının) çalışmasına bağlıdır.
  • En-az-bir-kez gönderim. Kuyruk ve hub gönderimi kopya üretebilir; istemci tarafında tekilleştirme yapılmaz.
  • Etiket süzgeci hub'da farklı çalışır. Hub-only modda tag hub'ın link parametresine (tam eşleşme) eşlenir.
  • Kayıt silme/düzenleme MCP araçlarında yoktur; yalnızca ekleme ve okuma desteklenir.

Eklenti (Plugin) Geliştirme

YDevDesk'i kaynak kodunu derlemeden genişletebilirsiniz. Çalışma zamanı eklentileri standart HTML, CSS ve JavaScript ile yazılır ve güvenli bir sandbox="allow-scripts" iframe içinde çalışır.

Klasör Yapısı

Her eklenti kendi klasöründe yaşar. Klasör adı yalnızca harf, rakam, - ve _ içermelidir:

Çekirdek Modül SDK (Kaynak Kod Katkısı)

YDevDesk deposuna doğrudan yeni bir yerleşik panel katkısında bulunmak isterseniz registry.ts, Workspace.tsx veya TitleBar.tsx dosyalarını düzenlemenize gerek yoktur. src/modules/<id>/manifest.ts dosyası Vite tarafından otomatik keşfedilir.

src/modules/my_module/manifest.ts 
import { Box } from "lucide-react";
import type { ModuleManifest } from "../../sdk/moduleSdk";
import MyPanel from "./MyPanel";

const manifest: ModuleManifest = {
  id: "my_module",
  title: "Modül Başlığı",
  description: "Kısa panel açıklaması",
  icon: Box,
  component: MyPanel,
  width: 320,
  order: 100,
};

export default manifest;

Panel bileşeninizin içinde useModuleSDK("my_module") hook'u ile tüm çekirdek servislere erişebilirsiniz:

src/modules/my_module/MyPanel.tsx 
import { useModuleSDK, useVisibilityPoll } from "../../sdk/moduleSdk";

export default function MyPanel() {
  const sdk = useModuleSDK("my_module");

  // Pencere gizliyken otomatik duran polling
  useVisibilityPoll(() => {
    // Periyodik veri güncellemesi
  }, 15000);

  return (
    <div className="p-3">
      <button onClick={() => sdk.terminal.run("git status")}>
        Durumu Kontrol Et
      </button>
    </div>
  );
}
  • sdk.terminal.run(cmd) — Aktif terminalde komut çalıştırır.
  • sdk.markdown.open({ path, title }) — Merkez sekmede Markdown dosyası açar.
  • sdk.notify(title, body) — Masaüstü bildirimi gönderir.
  • sdk.storage.get / set — Modüle özel izole yerel depolama.
  • sdk.connections.projectRoots — Ayarlardaki proje kök dizinleri listesi.
